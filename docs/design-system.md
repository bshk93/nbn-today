# Design system

Adopted 2026-09-24. Before it, every page defined its own container width,
header, tabs, tables and buttons, so the site read as modules dropped onto a
page: ten page widths, three header layouts, four tab styles, 67 font sizes,
147 local button rules. This is what replaced them.

## Where things live

| File | What it holds |
|---|---|
| `css/theme.css` | Tokens. Colour per theme; type scale (`--text-xs` … `--text-xl`), spacing (`--space-1` … `--space-7`), page widths, radii and fonts are theme-independent and live only in the bare `:root`. The 30 team blocks are generated by `build/make_team_theme.py`, which skips the non-colour tokens. |
| `css/components.css` | The shared pieces, all prefixed `ui-`. Imported by `css/nav-chrome.css`, so every page has them, including `team.js`'s injected page. |
| `css/fonts.css` | Inter (body) and Barlow Condensed (display: titles and big numbers only). Both self-hosted. |
| `css/team-colors.css` | `[data-team="ABC"]` → `--team-primary` / `--team-accent`. **Generated** by `build/make_team_colors_css.py` from `build/team-colors.json`; the pre-commit hook fails if they disagree. |
| `names.js` | `nbnPlayerName("MCCOLLUM, CJ")` → `"CJ McCollum"`. Use it instead of writing another name formatter. |

## Components (`css/components.css`)

- **Container:** `ui-page` (960px) or `ui-page ui-page--wide` (1240px). A few pages keep their own width on purpose: the 30×30 grid (h2h), the games, the article views, the live draft show.
- **Header:** `ui-header` > `ui-title` + `ui-subtitle`, with `ui-header-actions` on the right.
- **Tabs:** `ui-tabs` / `ui-tab` switch between *sections of a page*. `ui-segmented` switches between *views of the same data*. Nothing else.
- **Back button:** a tab switch, or opening another item on the same page (a day, a season, a team, a stat board), is `history.pushState`, and the page listens for `popstate` to redraw it, so Back returns to it. Filters, sorting and search only `replaceState`, or five filter clicks take five Backs to leave. Name the tab in the URL (`#tab`) and read it on load, so a link lands on it too.
- **Section title:** `ui-section-title`. Sentence case at a real size, not tiny spaced capitals.
- **Table:** `ui-table-wrap` > `ui-table`. `.num`/`.right`, `.center`, `.muted`, `.strong` cells; `ui-table--dense`, `ui-table--sticky-first`. The wrap scrolls sideways on a phone so a table never widens the page.
- **Buttons:** `ui-btn` plus `--primary`, `--danger`, `--ghost`, `--sm`. The older names pages already used (`.btn`, `.btn-primary`, `.btn-ghost`, `.btn-danger`, `.btn-secondary`, `.btn-success`, `.btn-cancel`, `.btn-save`, `.btn-sm`) are styled as the same buttons, so don't redefine them locally.
- **Form fields:** a zero-specificity `:where()` base gives every control the same font, colours, border and focus ring. `ui-input`/`ui-select`/`ui-textarea`/`ui-label` for new forms.
- **Other:** `ui-card`, `ui-badge` (tones), `ui-empty`, `ui-loading`, `ui-prose` (long-form text and rendered markdown).

## Rules worth knowing

- **Why `ui-` prefixes:** `.tabs`, `.tab`, `.page-header` and `.section-title` already meant different things on 20 pages. An unprefixed shared rule would have leaked into them.
- **Why some shared rules start with `:root`:** a page's `<style>` loads after `components.css` and wins at equal specificity. Rules that must override a page's own (the display-face titles, the team band, the homepage layout) carry `:root` for weight, not scope.
- **Heat-map cells** (OVR, ratings, head-to-head) are a translucent tint of the hue plus text at `--heat-text-l`, which is darker on light themes. Never a fixed dark background: that looked muddy and broke light themes.
- **Signing in** is the header's job: `token-badge.js` puts a Sign in button in the nav, and `nbnSignOut()` in `nav.js` is the one sign-out, in the profile menu. Pages don't carry their own sign-in bars; a page that needs a sign-in says so in a line of text.
- **Check phones.** Every page was checked at 390px wide for no horizontal overflow. A new page should be too.
- **Motion is subtle and lives in `components.css`** (§ Motion): the page fades in once, the homepage cards rise in one after another, and cards that are links lift on hover. Big numbers count up with `nbnCountUp(el)` from `nav.js`. All of it is off under `prefers-reduced-motion`. Page containers only fade, never move: a transform on them would trap any `position: fixed` dialog inside.
- **Small team logos come from `logos/sm/logo-{abbr}.webp`** (96px, ~4KB each), not `logos/logo-{abbr}.png` (480px, up to 120KB). Use the full size only where a logo is drawn bigger than about 48px: the team band and the champions banner. `build/make_logo_thumbs.py` regenerates them.
- **Icons** (favicon, apple-touch-icon, the manifest's) are in `icons/`, made from `logo.png` by `build/make_icons.py`. The `<link>` tags are written into every page's head by `build/og_tags.py`, so a new page gets them with its OG entry.

## Sidebar (`css/sidebar.css`, built by `nav.js`)

The site's left-hand nav, on every page that runs `nav.js`. **The links are `NAV_SECTIONS` in `nav.js`** — the same list Ctrl+K search reads (`SITE_PAGES` / `ROLE_PAGES` are derived from it), so a new page is one row there. The homepage's link tiles are still a separate list in `index.html`; until they're merged, add a page to both.

- **States live on `<html>`.** At 900px and up the sidebar is docked: `data-sidebar="open"` (15rem) or `"rail"` (3.5rem, icons only), the visitor's choice, stored in `localStorage.nbn_sidebar`. Below 900px it's an overlay drawer opened by the ☰ that `_initNav` adds to `.nav` (`.sb-drawer-open`).
- **No shift on first paint.** `theme-boot.js` sets `data-sidebar` in `<head>`, and the CSS reserves the space with `margin-left` on `body` before `nav.js` (end of `<body>`) draws the sidebar. Keep `theme-boot.js` and `_sidebarMode()` on the same key and default.
- **Layering:** docked, it's `z-index: 50`, under any page's own modal scrim (100 and up). The drawer is 9000, under search (9999) and the nav menus (10000).
- **Row fields:** `short` is the sidebar label when the search title is long, `roles` hides a row (in search too) until `/api/me` says this member holds one (admin always does; `[]` is admin-only), and `searchOnly` keeps a deep link (a tab, an anchor) out of the sidebar.
- **Icons** are a two-colour set in `icons/nav-icons.svg`, generated by `build/make_nav_icons.py` (edit there, then run it). Each row names one by id (`icon: 'calendar'`). The body is the theme's `--accent`, the detail is `--text-on-accent`, and the soft shadow is CSS (`.ni`). Rule for new ones: a white detail only ever sits on top of the accent body, never on the page, or it disappears on light themes. Search results use the same icons.
- **Opting out:** `<html data-no-sidebar>`. No page needs it today.
- **Folded sections** are remembered in `localStorage.nbn_sidebar_groups`. The section holding the current page is always drawn open, and in rail mode every section shows.
