# Design system

Adopted 2026-09-24. Before it, every page defined its own container width,
header, tabs, tables and buttons, so the site read as modules dropped onto a
page: ten page widths, three header layouts, four tab styles, 67 font sizes,
147 local button rules. This is what replaced them.

## Where things live

| File | What it holds |
|---|---|
| `css/theme.css` | Tokens. Colour per theme; type scale (`--text-xs` … `--text-xl`), spacing (`--space-1` … `--space-7`), page widths, radii and fonts are theme-independent and live only in the bare `:root`. The 30 team blocks are generated by `build/make_team_theme.py`, which skips the non-colour tokens. |
| `css/components.css` | The shared pieces, all prefixed `ui-`. Imported by `css/nav-chrome.css`, so every page has them, including `team.js`'s injected page. |
| `css/fonts.css` | Inter (body) and Barlow Condensed (display: titles and big numbers only). Both self-hosted. |
| `css/team-colors.css` | `[data-team="ABC"]` → `--team-primary` / `--team-accent`. **Generated** by `build/make_team_colors_css.py` from `build/team-colors.json`; the pre-commit hook fails if they disagree. |
| `names.js` | `nbnPlayerName("MCCOLLUM, CJ")` → `"CJ McCollum"`. Use it instead of writing another name formatter. |

## The look: broadcast

Since 2026-10-23 the site aims to read like a sports broadcast rather than a SaaS dashboard. Before it, the site looked like every generated app: rounded bordered cards, pill chips, a gradient hero and emoji for icons. Four rules:

- **Type does the work, not boxes.** Barlow Condensed in capitals is the voice: page titles, tabs, section titles, table headers, chips, big numbers. Inter is for reading: body text, table cells, forms.
- **Square and flat.** `--radius-sm` is 2px and `--radius` 4px; no pills (circles stay for avatars and dots). No drop shadows except menus and dialogs, and no gradients except functional masks (the tab-strip fade).
- **Colour means something.** Chrome is neutral. Bright colour is a team's, a result (win/loss, up/down), or an alert.
- **Almost no motion.** A 150ms page fade. Nothing rises, staggers, lifts or counts up.

## Components (`css/components.css`)

- **Container:** `ui-page` (960px) or `ui-page ui-page--wide` (1240px). A few pages keep their own width on purpose: the 30×30 grid (h2h), the games, the article views, the live draft show. **Every container starts at the same left edge** (where a centred 1240px column would), whatever its width, so a title never moves sideways between pages; a narrow page's spare room is on the right.
- **The line above the title:** `.nav`, in the display face. A page with no back link of its own gets its sidebar section's name ("SEASON") from `NAV_SECTIONS` (`_activeSectionLabel` in `nav.js`); a page with a back link or breadcrumb ("← TEAMS") keeps it, in the same type. Pages don't style `.nav` themselves. Below 900px, where the sidebar is a closed drawer, the top row is chrome only: the menu button, the site's mark (`.nav-brand`, logo + NBN) and Sign in. `_initNav` wraps everything else in `.nav-trail`, which drops to its own line above the title. A toolbar that borrows `.nav` and carries its own `h1` (draft/pick) gets neither.
- **Header:** `ui-header` > `ui-title` + `ui-subtitle`, with `ui-header-actions` on the right.
- **Tabs:** `ui-tabs` / `ui-tab` switch between *sections of a page*. `ui-segmented` switches between *views of the same data*. Nothing else.
- **Back button:** a tab switch, or opening another item on the same page (a day, a season, a team, a stat board), is `history.pushState`, and the page listens for `popstate` to redraw it, so Back returns to it. Filters, sorting and search only `replaceState`, or five filter clicks take five Backs to leave. Name the tab in the URL (`#tab`) and read it on load, so a link lands on it too.
- **Section title:** `ui-section-title`: the display face in capitals at `--text-lg`. Not the tiny spaced Inter capitals pages used to have.
- **Kicker, rank, stat line:** `ui-kicker` (small label above a title), `ui-rank` (a list position in the display face), `ui-statline` (`<b>29</b><small>pts</small>`).
- **Scores:** a team in a score line carries its two colours as a pair of stripes (`.sb-edge` on `/boxscores`, the top edge of each side's card on `/preview`), never one: several primaries (Brooklyn black, Denver navy) vanish on a dark page alone. Set `data-team` on the element and read `--team-primary` / `--team-accent`.
- **Homepage sections** are ruled, not boxed: a 2px rule in `--text-primary`, then the section name in the display face (`:root .dash-card` in `index.html`).
- **The homepage feed** (Around the League) groups rows under a day header (`ui-kicker`), tags each with a `ui-chip` that is neutral unless its kind carries a tone (`FeedTypes.tone` in `feed-types.js`: accent for trades, danger for releases and waivers, warning for waiver ties and hard-cap levels), and draws a night's finals as a ticker grid, each side edged in its team's two colours.
- **Chip:** `ui-chip`, one square tag for categories, roles and flags, with the badge's tones; `ui-chip--team` takes `--chip-c`.
- **Table:** `ui-table-wrap` > `ui-table`. Every `th` on the site, ui-table or not, is the display face at `--text-base` (`:root:root th` in `components.css`, doubled so it outweighs a page's own `.x th` / `.x thead th` that loads after it; only an id-scoped rule still wins). `.num`/`.right`, `.center`, `.muted`, `.strong` cells; `ui-table--dense`, `ui-table--sticky-first`. The wrap scrolls sideways on a phone so a table never widens the page.
- **Buttons:** `ui-btn` plus `--primary`, `--danger`, `--ghost`, `--sm`. The older names pages already used (`.btn`, `.btn-primary`, `.btn-ghost`, `.btn-danger`, `.btn-secondary`, `.btn-success`, `.btn-cancel`, `.btn-save`, `.btn-sm`) are styled as the same buttons, so don't redefine them locally.
- **Form fields:** a zero-specificity `:where()` base gives every control the same font, colours, border and focus ring. `ui-input`/`ui-select`/`ui-textarea`/`ui-label` for new forms.
- **Other:** `ui-card`, `ui-badge` (tones), `ui-empty`, `ui-loading`, `ui-prose` (long-form text and rendered markdown).

## Rules worth knowing

- **Why `ui-` prefixes:** `.tabs`, `.tab`, `.page-header` and `.section-title` already meant different things on 20 pages. An unprefixed shared rule would have leaked into them.
- **Why some shared rules start with `:root`:** a page's `<style>` loads after `components.css` and wins at equal specificity. Rules that must override a page's own (the display-face titles, the team band, the homepage layout) carry `:root` for weight, not scope.
- **Heat-map cells** (OVR, ratings, head-to-head) are a translucent tint of the hue plus text at `--heat-text-l`, which is darker on light themes. Never a fixed dark background: that looked muddy and broke light themes.
- **Signing in** is the sidebar's job: the account block at its bottom left (`_buildAccount` in `nav.js`) signs in through `token-badge.js`'s button, which stays in the nav only on phones, and `nbnSignOut()` in `nav.js` is the one sign-out, in that menu. The theme picker lives there too. Pages don't carry their own sign-in bars; a page that needs a sign-in says so in a line of text.
- **Check phones.** Every page was checked at 390px wide for no horizontal overflow. A new page should be too.
- **Motion is almost none and lives in `components.css`** (§ Motion): the page fades in once over 150ms, and that is all. Off under `prefers-reduced-motion`. Page containers only fade, never move: a transform on them would trap any `position: fixed` dialog inside.
- **Small team logos come from `logos/sm/logo-{abbr}.webp`** (96px, ~4KB each), not `logos/logo-{abbr}.png` (480px, up to 120KB). Use the full size only where a logo is drawn bigger than about 48px: the team band and the champions banner. `build/make_logo_thumbs.py` regenerates them.
- **Icons** (favicon, apple-touch-icon, the manifest's) are in `icons/`, made from `logo.png` by `build/make_icons.py`. The `<link>` tags are written into every page's head by `build/og_tags.py`, so a new page gets them with its OG entry.

## Keeping it that way

- **The drift ratchet.** `build/check_design_drift.py` counts, per file, the literal font sizes, colours (outside `css/theme.css`), radii, gradients, shadows, emoji and bare `.page` containers, and the pre-commit hook fails if any count goes up against `build/design-drift-baseline.json`. A new file starts at zero. When a change lowers counts, `--update` locks them in; `--report` shows totals and the worst files.
- **Screenshots.** `tests/frontend/screenshots.js` captures a fixed list of pages at 1440px and 390px in the dark, light and a team theme, named so two runs line up file for file: one against `nbn.today`, one against a branch served by `build/preview_live.py`. It also fails on any page wider than a phone.

## Sidebar (`css/sidebar.css`, built by `nav.js`)

The site's left-hand nav, on every page that runs `nav.js`. **The links are `NAV_SECTIONS` in `nav.js`** — the same list Ctrl+K search reads (`SITE_PAGES` / `ROLE_PAGES` are derived from it), so a new page is one row there. It is the site's only page directory: the homepage's link tiles and its strip of 30 team logos were removed once every link was confirmed reachable from it (2026-10-22).

- **States live on `<html>`.** At 900px and up the sidebar is docked: `data-sidebar="open"` (15rem) or `"rail"` (3.5rem), the visitor's choice, stored in `localStorage.nbn_sidebar`; the expand/collapse button is at the top, beside the logo. Below 900px it's an overlay drawer opened by the ☰ that `_initNav` adds to `.nav` (`.sb-drawer-open`).
- **No shift on first paint.** `theme-boot.js` sets `data-sidebar` in `<head>`, and the CSS reserves the space with `margin-left` on `body` before `nav.js` (end of `<body>`) draws the sidebar. Keep `theme-boot.js` and `_sidebarMode()` on the same key and default.
- **Layering:** docked, it's `z-index: 50`, under any page's own modal scrim (100 and up). The drawer is 9000, under search (9999) and the nav menus (10000).
- **Row fields:** `short` is the sidebar label when the search title is long, `roles` hides a row (in search too) until `/api/me` says this member holds one (admin always does; `[]` is admin-only), and `searchOnly` keeps a deep link (a tab, an anchor) out of the sidebar.
- **Icons** are a two-colour set in `icons/nav-icons.svg`, generated by `build/make_nav_icons.py` (edit there, then run it). **Section headers carry them; the rows under a header are plain text**, indented to its name. A section names its header icon (`icon:` on the section); a row's own `icon` is what search results show. No icon sits on a backing tile: each is the object itself or a bare glyph. Two colours per icon, all from the theme: the body is `--accent`, detail drawn on the body is `--text-on-accent` (white), and a bare glyph's second tone is a light tint of the accent (`--ni-c`). The soft shadow is CSS (`.ni`). Rule for new ones: white only ever sits on top of the accent body, never on the page, or it disappears on light themes.
- **Search and the inbox live in the sidebar:** its search box (or Ctrl+K), and the **Inbox** entry directly under Teams (`_buildInboxEntry`), which carries the unread count. The count also shows on the avatar and, on phones, as a dot on the ☰. The nav's top-right is left with only token-badge.js's Sign in, on phones.
- **Opting out:** `<html data-no-sidebar>`. No page needs it today. A page that opts out gets search and inbox buttons back in its nav.
- **Account block** (bottom left, like Claude's): avatar or initials, name, and team with its record. Click it for a menu with My profile, your team, Inbox, NB¥ history, the Theme list and Sign out. Signed out, it's a Sign in button whose menu still offers themes. It replaced the nav's profile and theme buttons. Its lookups (`_fetchMe`, `_fetchMyTeam`, `_fetchBalance`, `_fetchProfile` in `nav.js`) are each made once per page and shared; `_fetchProfile` also keeps the unlocked-theme cache fresh, so it runs on every signed-in page.
- **Pinned** sits above the sections, per browser (`nbn_sidebar_pins`, hrefs resolved against `NAV_SECTIONS` each time, so a page that leaves the nav drops out). Left out while empty. There is deliberately no Recent list: apart from pins, the sidebar is the same on every page.
- **Teams** is its own entry at the top (`_buildTeamsEntry`): hover or click opens a panel to the right with all 30 teams by division (`TEAM_DIVISIONS`, beside `TEAM_LIST`), logos loaded on first open, and an All teams link to `/teams`. In the phone drawer it unfolds in place.
- **Rail mode** shows only the header icons; clicking one opens the sidebar on that section. A header shows its rows' badge total while they're out of sight (folded, or rail).
- **Badges** come from `_setBadge(href, n, label)`: unread inbox (`_unreadCount`, shared with the nav button) and today's games (`/api/schedule`, cached in `sessionStorage` for 10 minutes).
- **Committee badges** count what's waiting on this member, by the same rule each page uses to mark a row as theirs. If you change a page's rule, change its `_…Work` function in `nav.js` with it: TRC (`renderRequest`'s `mine`: unvoted ballots, trades ready to finalize for the head, trades awaiting your team's consent), PDC (the list tabs: your unballoted free agents, the unblocked agents' queue, needs-a-result), Stats (`renderTiles`' "Awaiting entry"), Stream (`openRequests`). They're fetched only for role holders, after the page is idle, and cached per tab for 2 minutes under the member's name. An owner with a trade awaiting their consent sees the TRC row even without a TRC role, since that's where the consent button is.
- **Sections start folded.** The ones a visitor unfolds are remembered in `localStorage.nbn_sidebar_open`. The section holding the current page is always drawn open, and in rail mode every section shows.
