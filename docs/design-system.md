# Design system

Adopted 2026-09-24. Before it, every page defined its own container width,
header, tabs, tables and buttons, so the site read as modules dropped onto a
page: ten page widths, three header layouts, four tab styles, 67 font sizes,
147 local button rules. This is what replaced them.

## Where things live

| File | What it holds |
|---|---|
| `css/theme.css` | Tokens. Colour per theme; type scale (`--text-xs` … `--text-xl`), spacing (`--space-1` … `--space-7`), page widths, radii and fonts are theme-independent and live only in the bare `:root`. The 30 team blocks are generated by `build/make_team_theme.py`, which skips the non-colour tokens. |
| `css/components.css` | The shared pieces, all prefixed `ui-`. Imported by `css/nav-chrome.css`, so every page has them, including `team.js`'s injected page. |
| `css/fonts.css` | Inter (body) and Barlow Condensed (display: titles and big numbers only). Both self-hosted. |
| `css/team-colors.css` | `[data-team="ABC"]` → `--team-primary` / `--team-accent`. **Generated** by `build/make_team_colors_css.py` from `build/team-colors.json`; the pre-commit hook fails if they disagree. |
| `names.js` | `nbnPlayerName("MCCOLLUM, CJ")` → `"CJ McCollum"`. Use it instead of writing another name formatter. |

## Components (`css/components.css`)

- **Container:** `ui-page` (960px) or `ui-page ui-page--wide` (1240px). A few pages keep their own width on purpose: the 30×30 grids (h2h, tradevotes), the games, the article views, the live draft show.
- **Header:** `ui-header` > `ui-title` + `ui-subtitle`, with `ui-header-actions` on the right.
- **Tabs:** `ui-tabs` / `ui-tab` switch between *sections of a page*. `ui-segmented` switches between *views of the same data*. Nothing else.
- **Section title:** `ui-section-title`. Sentence case at a real size, not tiny spaced capitals.
- **Table:** `ui-table-wrap` > `ui-table`. `.num`/`.right`, `.center`, `.muted`, `.strong` cells; `ui-table--dense`, `ui-table--sticky-first`. The wrap scrolls sideways on a phone so a table never widens the page.
- **Buttons:** `ui-btn` plus `--primary`, `--danger`, `--ghost`, `--sm`. The older names pages already used (`.btn`, `.btn-primary`, `.btn-ghost`, `.btn-danger`, `.btn-secondary`, `.btn-success`, `.btn-cancel`, `.btn-save`, `.btn-sm`) are styled as the same buttons, so don't redefine them locally.
- **Form fields:** a zero-specificity `:where()` base gives every control the same font, colours, border and focus ring. `ui-input`/`ui-select`/`ui-textarea`/`ui-label` for new forms.
- **Other:** `ui-card`, `ui-badge` (tones), `ui-empty`, `ui-loading`, `ui-prose` (long-form text and rendered markdown).

## Rules worth knowing

- **Why `ui-` prefixes:** `.tabs`, `.tab`, `.page-header` and `.section-title` already meant different things on 20 pages. An unprefixed shared rule would have leaked into them.
- **Why some shared rules start with `:root`:** a page's `<style>` loads after `components.css` and wins at equal specificity. Rules that must override a page's own (the display-face titles, the team band, the homepage layout) carry `:root` for weight, not scope.
- **Heat-map cells** (OVR, ratings, head-to-head) are a translucent tint of the hue plus text at `--heat-text-l`, which is darker on light themes. Never a fixed dark background: that looked muddy and broke light themes.
- **Signing in** is the header's job: `token-badge.js` puts a Sign in button in the nav, and `nbnSignOut()` in `nav.js` is the one sign-out, in the profile menu. Pages don't carry their own sign-in bars; a page that needs a sign-in says so in a line of text.
- **Check phones.** Every page was checked at 390px wide for no horizontal overflow. A new page should be too.
