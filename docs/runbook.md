# Runbook — how the box is put together

**What this is:** the operating picture, as of 2026-08-19. Where things live,
what runs on its own, and what to do when something breaks.

**What this is not:** the reasoning. Every "why is it like this" answer is in
`docs/dev-deploy-setup-spec.md`, which is a design record — it argues the case,
records what was rejected, and tracks each step's status. This page assumes
those decisions and just says what the result is.

There is **no wildcard DNS**. A new subdomain needs its own A record at Porkbun.
`/etc/nginx/sites-enabled/nbn.today` is a **real file, not a symlink** into
`sites-available`, and the two have diverged — edit `sites-enabled`.

### Inside the data directory

Three lifecycles, distinguished by gitignore rather than by folder:

- **Irreplaceable** — `allstats-*.csv` (the box scores, 157k rows), the JSON
  state (`transactions.json`, `player-bios.json`, `team-state.json`, …), the
  per-team roster/picks/deadcap CSVs. Backed up.
- **Derived** — `derived/`, written only by the build. Not backed up; the build
  *is* its restore path.
- **Served** — `public/`, a symlink view unifying the two under the URL paths
  pages already fetch. Regenerated by `build/link-public.sh` at the end of every
  build. This is what nginx's `\.csv$` block points at.

## What runs on its own

| Unit | Schedule | What it does | If it fails |
|---|---|---|---|
| `nbn-api` | always | the API on :8001 | site loses every dynamic page; `journalctl -u nbn-api -n 50` |
| `nbs-snapshot` | every 10 min | commits the data dir, pushes to `bshk93/nbn-data` | backup stops leaving the box — it exits non-zero so `systemctl status` shows it |
| `poopoo` | every 10 min | regenerates the cap-sheet diff at `/poopoo` | `/poopoo` goes stale; nothing else |
| `nbn-achievements` | every 10 min | awards NB¥ for newly unlocked achievements | awards pause; the snapshot is monotonic so nothing double-fires |
| `nbs-drive-backup` | Sundays 04:00 | tarball of the tracked set to Google Drive | third backup tier stops; the other two continue |
| `nbs-integrity` | Mondays 09:00 | box score row counts + closed-season hashes | **investigate immediately** — see below |

Nothing else is scheduled. The stats build is **not** on a timer; it is
triggered by a box score commit.

## The three flows

**A box score becomes site data.**

```
/boxscores/submit  →  API appends to allstats-{season}.csv   (append-only guard)
                   →  triggers build/build.sh
                   →  stats_build reads the raw CSVs, writes derived/
                   →  link-public.sh republishes public/
                   →  nginx serves it immediately
```

The append is guarded: `routers/allstats_guard.py` refuses any write that
shrinks the file, rewrites rows already on disk, or drops a column. Each commit
also appends one line to `boxscore-provenance-{season}.jsonl` — the screenshots
are deleted after parsing, so that line is the only record of where a game came
from.

**A transaction becomes league state.** `POST /api/transactions` validates
against the rulebook, writes rosters/bios/team-state, appends to
`transactions.json`, and posts to Discord. **It applies for real when its checks
pass — it is not a dry run.** The read-only equivalents are `/api/validate/*`.

**A code change becomes live.**

```
cd ~/projects/nbn-today-dev     # edit on a branch, commit, push, merge to main
cd ~/projects/nbn-today && ./deploy.sh
```

`deploy.sh` refuses a dirty tree, pulls `--ff-only`, prints the rollback
command, and (for the API) restarts the service and checks it came back. It
refuses to run from a `-dev` checkout.

## Backups — three tiers, and a proven restore

| Tier | Where | Covers |
|---|---|---|
| every 10 min | `/var/lib/nbs-backup.git` | logical corruption — a bad write is one `git diff` away |
| every 10 min | `github.com/bshk93/nbn-data` (private) | disk or VPS loss |
| weekly | Google Drive tarball | provider or account loss |

The Drive tarball excludes credentials: `google-oauth.json` is dropped and
`members.json` goes in **redacted** — tokens blanked, roles and tenures kept.

**Restoring** (drilled 2026-08-19, all 86 derived CSVs came back byte-identical):

```bash
git clone git@github.com:bshk93/nbn-data.git ~/nbs-restore
NBS_DATA_DIR=~/nbs-restore NBN_OUT_DIR=~/nbs-restore/derived \
  bash ~/projects/nbn-today/build/build.sh
chmod 600 ~/nbs-restore/members.json      # git does not preserve modes
```

`sessions.json` and `tokens.json` are deliberately absent — every member signs
in again. `owners.csv` is absent and regenerated by the build.

## When something breaks

| Symptom | First move |
|---|---|
| Site serves but every dynamic page is empty | `systemctl status nbn-api`, then `journalctl -u nbn-api -n 50` |
| A page shows no data, others fine | did the build fail? `tail -50 /var/log/nbn-build.log` |
| Stats look wrong after a game | rerun the build: `bash build/build.sh`. Nothing in `derived/` is authored, so rerunning is always safe |
| **`nbs-integrity` failed** | a box score file lost rows or a closed season changed. **Do not run a build.** `git --git-dir=/var/lib/nbs-backup.git log -- <file>`, restore, then `check_stats_integrity.py --accept` |
| A box score commit 500s with "not an append" | the guard caught something. Read the message — it names the file and what would have been lost |
| Build fails with `No module named stats_build` | the site deployed ahead of the API. Deploy `nbn-api` — it owns the engine |
| Stats wrong in a way that smells like the port | `NBN_STATS_ENGINE=r bash build/build.sh` puts R back for one run, then say so in `docs/stats-pipeline-port-spec.md` |
| Bad deploy | `git reset --hard <sha>` (the sha `deploy.sh` printed), plus a restart for the API |
| Cap numbers disagree with the league sheet | `/poopoo` is the diff; regenerate with `build/venv/bin/python3 build/poopoo.py` |

**Rollback is code-only.** Data recovery is the backup repo, never a git reset
in a code checkout.

## Known gaps

- **`DISCORD_ALERT_CHANNEL` is unset**, so an integrity violation is
  journal-only. The unit still exits non-zero.
- **The backup repo carries live credentials** — member tokens, the Google
  refresh token, and session ids in the history from before 2026-08-19. Private
  repo; filed P2 in `BACKLOG.md`.
- **R is still installed, and stays** — not a gap, a decision (2026-08-19). It
  is the stats build's rollback (`NBN_STATS_ENGINE=r`) *and* its only
  value-level oracle: `smoke_test.py` asserts schema and no values, so
  `harness port` diffing both engines is the one thing that checks the numbers.
  Watch item, not a countdown: the first time the playoff/awards/rings paths
  run on new data (26-27 playoffs), run `harness port` and confirm R agrees.
- **Two different answers to "what season is it?"** — the API and the submit
  page. The build's third copy went at the cutover; it now shares the API's
  process but not its function (`stats_build/buildargs.py`). `BACKLOG.md` P2.
